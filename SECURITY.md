# 🛡️ Информационная безопасность

Документ описывает меры безопасности, реализованные в платформе проектных офисов.

## 🔐 Реализованные меры безопасности

### 1. Аутентификация и авторизация

#### JWT токены
- Использование JSON Web Tokens для аутентификации
- Токены имеют ограниченное время жизни (настраивается через `JWT_EXPIRES_IN`)
- Секретный ключ хранится в переменных окружения (`.env`)
- Каждый токен содержит ID пользователя, роль и ID офиса

#### Управление сессиями
- Сессии хранятся в базе данных MySQL
- Возможность просмотра активных сессий
- Принудительное завершение сессий
- Автоматическая очистка истёкших сессий

#### Ролевая модель доступа (RBAC)
- 5 ролей пользователей с различными правами
- Проверка прав доступа на уровне middleware
- Контроль доступа к проектам на основе назначения

### 2. Защита паролей

#### Хеширование
- Использование bcrypt с 10 раундами соли
- Пароли никогда не хранятся в открытом виде
- Минимальная длина пароля настраивается (по умолчанию 8 символов)

#### Политика паролей
- Настраиваемые требования к сложности:
  - Минимальная длина
  - Заглавные буквы
  - Цифры
  - Специальные символы

#### Защита от brute-force
- Ограничение попыток входа (по умолчанию 5)
- Автоматическая блокировка аккаунта после превышения лимита
- Настраиваемое время блокировки (по умолчанию 15 минут)
- Rate limiting на уровне API (5 запросов за 15 минут)

### 3. Защита от уязвимостей

#### SQL Injection
- Использование параметризованных запросов (mysql2)
- Отключение множественных запросов (`multipleStatements: false`)
- Валидация всех входных данных через express-validator

#### XSS (Cross-Site Scripting)
- React автоматически экранирует вывод
- Content Security Policy (CSP) заголовки через Helmet
- Запрет inline-скриптов из внешних источников

#### CSRF (Cross-Site Request Forgery)
- Использование JWT токенов вместо cookies
- Проверка Origin/CORS заголовков
- SameSite атрибуты для cookies

#### Clickjacking
- HTTP заголовок `X-Frame-Options: SAMEORIGIN`
- Запрет встраивания сайта в iframe

#### MIME Sniffing
- Заголовок `X-Content-Type-Options: nosniff`
- Предотвращение неправильной интерпретации типов файлов

### 4. HTTP безопасность (Helmet)

Реализованы следующие заголовки:
```
Content-Security-Policy
X-Frame-Options: SAMEORIGIN
X-Content-Type-Options: nosniff
X-XSS-Protection: 1; mode=block
Referrer-Policy: no-referrer-when-downgrade
Strict-Transport-Security (при использовании HTTPS)
```

### 5. Rate Limiting

#### Общие лимиты
- 100 запросов за 15 минут для всех API endpoints
- 5 запросов за 15 минут для endpoint входа
- Настраиваемые лимиты через переменные окружения

#### Защита от DDoS
- Ограничение размера тела запроса (10 MB)
- Ограничение количества подключений к БД (10)
- Таймауты для соединений

### 6. Шифрование данных

#### Транзит данных
- Обязательное использование HTTPS в продакшене
- TLS 1.2+ для всех соединений
- Шифрование паролей при передаче

#### Хранение данных
- Чувствительные данные (пароли) хешируются
- JWT секреты хранятся в переменных окружения
- Конфигурация БД не коммитится в репозиторий

### 7. Аудит и логирование

#### Аудит действий
- Логирование всех критических действий:
  - Вход/выход из системы
  - Создание/изменение/удаление сущностей
  - Изменение настроек
  - Смена паролей

#### Информация в логах
- ID пользователя
- IP адрес
- User Agent
- Время действия
- Детали операции (JSON)

#### Защита логов
- Логи доступны только администраторам
- Автоматическая ротация (настраивается)
- Защита от модификации

### 8. Валидация данных

#### На уровне API
- express-validator для всех входных данных
- Проверка типов данных
- Проверка длины строк
- Проверка форматов (email, URL, дата)

#### Санитизация
- Trim пробелов в строках
- Экранирование специальных символов
- Ограничение размеров данных

### 9. Контроль доступа к ресурсам

#### Проектный уровень
- Проверка доступа к проектам через middleware
- Ролевая модель:
  - Admin: полный доступ
  - Office Director: доступ к проектам своего офиса
  - Project Manager: доступ к назначенным проектам
  - Team Member: доступ к назначенным проектам
  - Viewer: только чтение

#### Функциональный уровень
- Разграничение прав по функциям:
  - Создание офисов (только admin)
  - Управление пользователями (только admin)
  - Изменение настроек (только admin)
  - Просмотр аудит логов (только admin)

### 10. Безопасность базы данных

#### Конфигурация MySQL
- Отдельный пользователь для приложения
- Минимальные необходимые привилегии
- Отключение удалённого root доступа
- Использование SSL для соединений (рекомендуется)

#### Резервное копирование
- Автоматические бэкапы (скрипт `backup.sh`)
- Шифрование бэкапов (рекомендуется)
- Тестирование восстановления

## 🔧 Рекомендации по усилению безопасности

### Критические (обязательные)

1. **Измените JWT_SECRET**
   ```bash
   node -e "console.log(require('crypto').randomBytes(64).toString('hex'))"
   ```

2. **Используйте HTTPS**
   - Получите SSL сертификат (Let's Encrypt)
   - Настройте редирект с HTTP на HTTPS
   - Включите HSTS

3. **Настройте firewall**
   ```bash
   sudo ufw allow 22    # SSH
   sudo ufw allow 80    # HTTP
   sudo ufw allow 443   # HTTPS
   sudo ufw enable
   ```

4. **Обновляйте зависимости**
   ```bash
   npm audit
   npm audit fix
   ```

### Важные (рекомендуемые)

5. **Двухфакторная аутентификация (2FA)**
   - Реализовать TOTP (Google Authenticator)
   - Обязательная для администраторов

6. **Мониторинг безопасности**
   - Fail2ban для защиты от brute-force
   - SIEM система для анализа логов
   - Alerting при подозрительной активности

7. **Регулярное тестирование**
   - Penetration testing (ежеквартально)
   - Vulnerability scanning (ежемесячно)
   - Code review перед релизом

8. **Backup стратегия**
   - Ежедневные инкрементальные бэкапы
   - Еженедельные полные бэкапы
   - Тестирование восстановления (ежемесячно)
   - Хранение бэкапов в разных локациях

### Дополнительные (опциональные)

9. **Web Application Firewall (WAF)**
   - Cloudflare WAF
   - AWS WAF
   - ModSecurity

10. **Docker security**
    - Non-root пользователь в контейнере
    - Read-only файловая система
    - Resource limits (CPU, memory)
    - Security scanning (Trivy, Snyk)

11. **Secrets management**
    - HashiCorp Vault
    - AWS Secrets Manager
    - Kubernetes Secrets

12. **API Security**
    - API Gateway (Kong, AWS API Gateway)
    - OAuth 2.0 для внешних интеграций
    - API versioning

2. **Изоляция**

3. **Анализ**
   - Сбор доказательств
   - Определение масштаба
   - Выявление уязвимости

4. **Устранение**
   - Патч уязвимости
   - Сброс скомпрометированных данных
   - Уведомление пользователей

5. **Восстановление**
   - Восстановление из бэкапа (если необходимо)
   - Проверка целостности данных
   - Возобновление работы

6. **Post-mortem**
   - Анализ причин
   - Обновление процедур
   - Обучение команды
